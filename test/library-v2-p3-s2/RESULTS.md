## Final policy refinement (follow-up commit on 43366d1; Owner decisions D1-D3)
- **D1 clone completeness - unchanged, DEFERRED TO P3-S5.** cloneCompleteness keeps the Design R1 semantics; the source carries an explicit note "revisit in P3-S5 before clone is user-facing; cloneSource.nodeCount must not become a permanent live checksum" (asserted by a source-guard test). Not a blocker for S3/S4.
- **D2 code canonicalization.** One reusable policy canonicalizeNodeCode (version 1): trim -> Unicode NFKC -> case-insensitive fold (toUpperCase then toLowerCase, locale-independent, no toLocale*) -> NFKC -> trim; no diacritic stripping, no inner-whitespace collapsing. Used by codeInUse (builders) and validateTree (duplicate detection). The stored/displayed code is the user text (trim only; never upper-cased or normalized). Tests: whitespace, upper/lower case, NFC/NFD, full-width forms and ss/sharp-s collide; distinct codes stay distinct; idempotence; null/blank; builders refuse equivalent duplicates on create and update; the emulator suite proves the Rules do NOT enforce uniqueness (a raw canonical duplicate is accepted, then flagged by validateTree and blocks activation) - client/domain duplicate prevention only, concurrent clients may race. P4 must reuse this helper.
- **D3 framework ordering - unchanged** (active, draft, archived, then newest first; client-side; no orderBy, no composite index, firestore.indexes.json untouched).

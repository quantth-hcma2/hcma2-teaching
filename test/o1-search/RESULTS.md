# O1 (Add-Teacher exception search) - candidate test results

Candidate branch `candidate/o1-add-teacher-exception-picker`, built directly on the released production baseline `d87f53516b7c66af57669fa195f53ac19f1b9d72` (O2). Scope: replace the paged / multi-select Add-Teacher picker by an explicit, bounded email-prefix search (Enter / TÌM only, minimum 3 characters, display 20, query `limit(21)`), one teacher per click, S4 membership authority unchanged. No name search, no new index, no `users` marker, no candidate collection, no backend, no bulk add, no O3, no P2-S5, no Rules/index/Storage change. Not released.

## Suites
- `unit.test.mjs` 12/12 (pure, fake dependencies): constants (min 3, display 20, query 21, `via`); normalization; the exact query constraints (range both ends with U+F8FF, `orderBy email`, `limit 21`, no role/status filter, no cursor); a term shorter than 3 characters is rejected before Firestore is touched; 20 shown + `more` only at 21 documents; classification of every row kind (a membership of any status always wins); all markup states and Vietnamese strings (escaping, no checkbox/TẢI THÊM/global claim, one add button only for eligible rows, archived Organization); the sequence guard (stale-result protection); the DOM-free write core (S4 contract payload, fresh user/Organization/exact-membership re-checks, never recreates active/suspended/removed/org_admin, archived/gone, second attempt cannot duplicate, failed write retryable, audit failure never fails the membership, never throws).
- `source-guard.test.mjs` 6/6 (pure): `index.html` delta vs the released O2 baseline is exactly three edits and reversing them restores `d5aa6c45...`; every old-picker symbol is gone (module and `index.html`); the exact query and its single `users` mention, one `getDocs`, no cursor/loop/unbounded read, the 20/21 constants documented as a UX cap and absent from Rules/index/schema files; **no timer, debounce or input listener - search runs only on form submit (Enter/TÌM)** with the sequence guard wired to every search and to close/Esc; the write core order (re-reads, plan, write, audit), one add-button markup, no bulk/select-all, only the two existing audit actions, `via: "exception-search"`; O2 module, approval code, member list/lifecycle, S2/S3 modules, Rules, indexes, Storage, package and vendor byte-pinned.

## Rewritten / updated earlier tests (legitimate maintenance)
The S4 tests that intentionally pinned the old discovery UX were rewritten, not kept in parallel: `test/library-v2-p2-s4/unit.test.mjs` (old picker markup/query tests removed), `source-guard.test.mjs` (collections guard no longer names the picker; summary slice marker; audit-action order), `membership.rules.test.mjs` (the picker query test became the email-search query test), `browser.e2e.mjs` (every picker step now uses the search dialog: add one, add several one at a time, associated/removed rows, duplicate race, large-population add, archived mid-flow, mobile). The O2 and S3 guards reverse the O1 edits first through the shared helper `test/o1-search/o1-edits.mjs`, and the O2 guard no longer pins the membership view (O1 owns it now).
